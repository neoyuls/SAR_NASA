## 1. What it is

A web app that lets anyone compare three cities over the same two-year window and understand why one
of them barely moves at all — with the 62-date series drawn whole, because the app has no time
control.

| Capability | What the user does |
|---|---|
| **Series across the window** | The series tab draws all 62 dates at once. The **map** shows the first/last snapshot only (the contract carries `val_t1`/`val_t2`, not a per-date grid). There is **no date slider** — the only slider filters on minimum coherence |
| **Click to interrogate** | Click a hexagon → the cell inspector shows its attributes and series; the committed artefacts aggregate the series at area level, and the panel says so instead of inventing one |
| **Shared scale (opt-in)** | A **Scale** radio switches from per-case colouring (the default) to one shared cross-city scale, so the three cities can be read against each other |
| **Filter** | Case, land use, minimum coherence, risk level, 3D extrusion and theme — six controls; there is no velocity-threshold filter |
| **Evidence** | Every rendered number carries a unit or says the unit is not declared; each group of figures prints one `Provenance ID` line, and the full source, date range and revisit interval sit in the provenance tab |
| **Learn** | Tab 4, **Provenance and limits**, explains NISAR, what SAR measures, what it cannot, and why Málaga is blank |

### The thesis the app must make visible

Subsidence is set by **interbed compressibility**, not by how much water is pumped.

| | **Mexico City** | **Jakarta** | **Málaga** |
|---|---|---|---|
| Aquifer | Lacustrine clay, closed basin | Deltaic soft clay, coastal | Thin detrital cover, confined karst |
| Regime | Mostly **inelastic** | Mixed | Mostly **elastic** |
| Subsidence | **−45 cm/yr** (published) | ~5 cm/yr avg; >1 m cumulative | mm–cm/yr |
| Failure mode | Land loss, faulting, drainage inversion | Inundation, capital relocation | Salinization, reservoir depletion |

> **The product insight:** on a shared legend, Málaga renders nearly flat. **That blankness is the
> finding** — and it is a data decision (one scale, honest units, published detection limit), not a
> paragraph of prose.

## 3. Using the app

Four tabs, one per question a reader actually asks:

1. **Map** — the H3 grid coloured by velocity (or the accessible blue–neutral–orange ramp), the
   filter strip, the shared-scale toggle, and a reading panel with the series and the KPIs for the
   filtered subset.
2. **Series and KPIs** — the whole 62-date series, its fitted trend and annual harmonic, and the
   KPIs that describe the grid behind it.
3. **Hazard and infrastructure** — the OpenStreetMap context layer, cross-referenced to the nearest
   filtered cell. A proximity cross-reference, never a hazard claim.
4. **Provenance and limits** — sensor, product, units, dates, the provenance record, the documented
   limitations and the raw `meta.json` fields.

The UI state is mirrored in the URL (`case`, `land`, `risk`, `coh`, `extrude`, `theme`, `scale`,
`cell`, `tab`, `ramp`), so a copied URL restores the cockpit; `?compact=1` collapses the filter strip
on a phone. Dark and light themes follow the system preference.

## 4. Architecture — compute offline, ship artefacts, render in Streamlit

The highest-risk failure mode in a 48 h demo is *live InSAR*. So the heavy work happens **before** the
app starts, and the app only reads small local artefacts.

```
┌──────────────────────────────────────────────────────────────┐
│ LAYER 1 — OFFLINE PIPELINE                                   │
│                                                              │
│  ASF / EGMS / HyP3                                           │
│        ↓  discover + download (resumable, size-guarded)      │
│  clip → reproject → physical conversion → quality filter     │
│        ↓  H3 res 9 aggregation, GIS enrichment               │
│  nisar_grid.parquet · timeseries.csv                         │
│  context_layers.geojson · meta.json        ← FROZEN contract │
└──────────────────────────┬───────────────────────────────────┘
                           │  stable, versioned data interface
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ LAYER 2 — STREAMLIT APP                                      │
│                                                              │
│  loaders → validation → filters → map → KPIs → charts        │
│                                                              │
│  No NASA downloads. No heavy processing. No science in the UI │
└──────────────────────────────────────────────────────────────┘
```

**Why this shape:** no server to fall over, no cold start mid-judging, no token expiry, and the
frontend never blocks on the pipeline — the mock respects the same schema, so swapping mock for real
data is a file replacement, not a code change.

- `app.py` only composes; it parses no artefact and computes no science.
- The pipeline never imports Streamlit.
- The UI never computes a geospatial quantity: if a number is not in an artefact, it does not exist.
- Thresholds, units and revisit intervals live in `src/domain/contracts.py` and `meta.json`, never
  duplicated in a component.

## 5. Data contract v1.1 — frozen

Four artefacts per case, under `data/processed/`. This is the whole interface between pipeline and
app; it is versioned, validated in code and locked by a regression suite.

| Artefact | Contents |
|---|---|
| `nisar_grid.parquet` | One row per H3 res-9 cell (~200 m): `cell_id`, `lat`, `lon`, `val_t1`, `val_t2`, `delta_change` (mm, cumulative), `velocity_mm_yr`, `seasonal_amp_mm`, `ratio_R`, `regime`, `coherence`, `land_use`, `risk_level`, `case_id`, `sensor`, `product`, `unit`, `velocity_unit`, `source`, `provenance_id` |
| `timeseries.csv` | `case_id`, `cell_id` (`"aoi"` = aggregate, H3 index = drill-down), `date`, `value` (mm), `trend_mm_yr`, `seasonal_mm`, `unit`, `sensor`, `product`, `quality`, `provenance_id` |
| `context_layers.geojson` | `FeatureCollection` in EPSG:4326: land use, infrastructure, hydrology, boundaries — each feature carries `layer`, `class`, `case_id`, `crs`, `source`, `provenance_id` |
| `meta.json` | `schema_version`, `case_id`, `name`, `bbox`, `crs`, `reference_point`, `dates`, `revisit_days`, `sensor`, `product`, `thresholds`, `provenance`, `stats`, `limitations`, `null_policy` |

Source of truth (code): `src/domain/contracts.py`.

**Version** `1.1`, revision 2, frozen 2026-11-14. **Fingerprint** `ed92be80…`
(`contract_fingerprint()`). A change means bumping `SCHEMA_VERSION`, recording why, and passing the
contract suite again.

Four rules that exist because they were ambiguous in the source documents:

1. **Cumulative vs rate.** `delta_change` is cumulative **mm**; the rate lives in `velocity_mm_yr`.
   One field cannot honestly be both.
2. **Product is declared, not assumed.** Closed enum, and it must be the product actually used —
   `nisar-gunw` or `mock` today. Labelling mock data `opera-disp-s1` would be a lie.
3. **Nothing is pooled across sensors.** Thresholds and `revisit_days` are per `(sensor, product)`;
   NISAR's 12-day coherence is not Sentinel-1's 6-day coherence.
4. **No sentinel values.** A cell without data is **absent**; it is never written as `0`. In Málaga,
   zero is a legitimate velocity and confusing it with nodata destroys the message.

Validate it:

```bash
./scripts/python.sh -m src.domain.contracts                                      # self-check: positives + negatives
./scripts/python.sh pipeline/validate_artifacts.py --processed data/processed    # file-level gate
./scripts/python.sh -m pytest tests -q                                           # contract + artefact suites
```

The gate is **fail-closed**: zero cases validated is a failure, and a `--case` filter that matches
nothing is a failure.

## 7. Science pipeline (offline)

`pipeline/` downloads (or synthesises) a stack, projects the line-of-sight displacement to vertical,
aggregates to H3 res 9, joins the context layers and writes the four artefacts. The scientific
reference for the physics, the window design and the identifiability conditions is
[`docs/science-guide.md`](docs/science-guide.md), which Tab 4 also quotes.

- **LOS → vertical.** One geometry, with the horizontal components assumed zero:
  `v_up = d_LOS/cosθ` (plus a `tanθ·(cosα·v_east + sinα·v_north)` term that vanishes unless a GNSS
  model supplies horizontals). "Purely vertical" is an assumption, not a measurement.
- **Trend and seasonal split.** Per-cell harmonic fit over the whole window (`harmonic_fit`): the
  two-year mock spans two annual cycles, so the amplitude is *fitted*, not typed. Below 0.75 year
  per harmonic the fit returns `seasonal_amp_mm = 0` meaning **not fitted**, `ratio_R` **null** and
  regime `transitional` — never a number invented to fill the gap.
- **Regime index.** `ratio_R = |velocity_mm_yr| / seasonal_amp_mm`, then `inelastic` / `transitional`
  / `elastic` from the frozen thresholds.
- **Risk band.** Displayed as a band derived from `|velocity_mm_yr|` (`< 5`, `5–25`, `≥ 25 mm/yr`),
  not as a separate measurement.

### Scattering physics: surface roughness, dielectric constant, L-band vs C-band

Three controls decide whether a surface can be measured at all, before any displacement is
estimated. They are brightness effects, not motion: this cockpit publishes `delta_change` and
`velocity_mm_yr` from phase, and never turns amplitude into a moisture or biomass claim.

- **Surface roughness.** A radar pixel returns a strong echo when the surface is rough at the scale
  of the wavelength and a weak, specular one when it is smooth: flat water sends the pulse away from
  the antenna, which is why open water decorrelates and is masked instead of measured. Roughness
  therefore gates observability; it does not enter the displacement arithmetic.
- **Dielectric constant.** The surface's complex dielectric constant sets how much of the pulse is
  reflected and how much penetrates. Liquid water raises it sharply, so wet soil and vegetation
  scatter more strongly than dry ground. That contrast is backscatter — useful for reading coherence
  and land cover, never converted into a stored-water number here.
- **L-band vs C-band.** NISAR's L-band wavelength (λ ≈ 0.2384 m, about 24 cm) is roughly four times
  longer than Sentinel-1's C-band (about 5.6 cm). The longer wavelength penetrates canopy and dry
  soil better and decorrelates more slowly, so a 12-day pair stays usable over a vegetated or dusty
  city; the cost is scale, since one fringe spans a larger displacement. Coherence is comparable
  only within one revisit interval and one band — never pool L-band and C-band numbers.

## 8. Data honesty and provenance

- **Mock is first-class.** `product: "mock"` is a declared value, not a placeholder: the schema, the
  filters, the map and the provenance are the same that a real granule would use. What changes is
  the source, and the app says which one is on screen.
- **Every payload carries `provenance_id`** (`{case_id}+{product}+{YYYYMMDD}+{sha256_8}`), and every
  figure group credits it. The provenance tab repeats the full record: source, method, processing
  date, reference and licence.
- **Málaga is the negative control.** Its rates sit at the detection floor (1.5 mm/year), and the
  bound *is* the result; the UI prints the limit and the sentence that says so instead of
  manufacturing a signal.
- **Mixed sensors or units are declared.** If a comparison ever mixes sensors, products or units,
  the comparison strip says so before the numbers are read.
- **No science in the UI.** Thresholds, regimes and risk bands come from the contract; the
  interface only labels them. `seasonal_amp_mm = 0` is shown as "not fitted", never back-filled.

## 13. Validation & limitations

![Cumulative displacement series](docs/figures/timeseries_three_cities.png)

*Cumulative displacement since the first acquisition, with Málaga's detection floor shaded
(±1.5 mm/yr over the window). The series are referenced to the first epoch, so they start at exactly
0 mm — and the seasonal bulge is visible mid-window rather than masquerading as secular motion.*

1. Málaga may sit at the detection floor — the bound *is* the result.
2. CDMX is not coastal; do not claim a coastal framing across all three cities.
3. NISAR GUNW posting is 80 m — city scale, not building scale.
4. NISAR urban coverage is not guaranteed: SME2 excludes urban areas, so an intersecting granule
   still needs visual verification before any city-wide claim.
5. Urban SAR flood mapping is confounded by double-bounce and shadow; use coherence-loss change
   detection, not thresholding.
6. Coherence depends on revisit interval; **NISAR 12-day ≠ Sentinel-1 6-day**. Never pool them.
7. "Changes in imagery" ≠ "changes on the ground" — layover and shadow move with the acquisition
   geometry.
8. Velocity is the calibrated claim; change detection is a supporting layer, not the headline.
9. **Vertical comes from one geometry, with the horizontal components assumed zero**
   (`v_north = 0`, `v_east = 0`, so `v_up = d_LOS/cosθ`). Real horizontal motion is therefore folded
   into the vertical rate, and the east sensitivity reaches ±0.63. **Sign and heading conventions
   are recorded, not validated:** `--los-sign` and `--heading-convention` are written into
   `provenance`, and `provenance.method` keeps its "not yet validated against GNSS" hedge — passing
   the flags restates the convention, it does not check it.
10. **No real granule has been downloaded or processed.** All three cases are `product: "mock"` and
    every artefact's own `limitations` says so; what this submission demonstrates is the schema, the
    pipeline and the map logic — not NISAR velocities.
11. **A stack shorter than three quarters of a year fits no annual harmonic, and still publishes a
    grid.** `seasonal_amp_mm` is then exactly 0.0 — meaning *not fitted*, never *no seasonality
    measured* — `ratio_R` is null, and `regime` is `transitional`. The two-year mock is unaffected:
    it spans two annual cycles and does publish a fitted amplitude.
12. **GNSS validation is still pending.** The intended check is a levelling or GNSS comparison with
    a target below 5 mm/yr RMSE; until it runs, the rates are what the artefacts declare and nothing
    more.
13. **Málaga's null result may come from NISAR or from EGMS.** Whichever source is used must be
    named in `provenance`, and the detection limit published either way: a null result without its
    bound is not a result.
